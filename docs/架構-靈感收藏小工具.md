# 架構規劃：靈感收藏小工具
> 日期：2026-11-03 ｜ 狀態：開發中（自動測試全過，待手機實測）｜ 來源需求：docs/需求-靈感收藏小工具.md
> ⚠️ 開工前先讀 CLAUDE.md 的「最高原則」

## 1. 使用形式
- 只有使用者本人使用，安卓手機 Chrome
- 裝在主畫面上，點開像 App（PWA，可安裝的網頁）
- 出現在安卓「分享」選單：從 IG、FB 分享連結進來；也可以從相簿分享照片進來
- 直接點開 → 第一頁是「新增」畫面（大多數時候是進來存資料）；「搜尋」在另一個分頁
- 開發程度：略懂（曾用 AI 協助完成一兩個小工具並部署到 GitHub Pages）

## 2. 系統拆分
| 模組 | 負責 | 不負責 | 對外接誰 |
|------|------|--------|----------|
| 新增畫面 | 照片（剪貼簿貼上／分享進來／點選檔案）、連結、分類按鈕、關鍵字、儲存 | 直接呼叫雲端 | 照片處理、送出佇列 |
| 分享接收 | 解析分享進來的文字與網址（從一段文字中抓出網址）、接收分享的圖片 | 儲存 | 新增畫面 |
| 照片處理 | 長邊縮到 1280px、轉 JPEG（約 100～300KB，省行動網路與雲端空間） | 裁切、濾鏡 | — |
| 送出佇列 | 存入 IndexedDB → 送出 → 成功才移除；失敗保留並在恢復網路、重開 App 時自動重試；顯示排隊數 | 畫面長相 | 連線層 |
| 連線層 | 呼叫雲端小程式的四個動作：save／list／update／delete，帶通行碼 | 重試 | 雲端小程式 |
| 雲端小程式 | 驗通行碼；照片寫入雲端硬碟資料夾「靈感收藏」並設知道連結可檢視；試算表增改刪；同 id 不重複 | 搜尋、畫面 | Google 雲端硬碟、試算表 |
| 搜尋 | 分類篩選＋多詞取交集＋單字／部分比對；新的在前 | 呼叫雲端 | — |
| 清單與單筆檢視 | 一列一筆（左小圖、右分類＋關鍵字）；大圖、開連結、修改、刪除 | 新增 | 連線層、搜尋 |
| 設定 | 雲端小程式網址、通行碼，存在 localStorage | 進原始碼 | — |
| App 外殼 | manifest（安裝與分享選單登記）、service worker（畫面檔離線快取、接收分享圖片） | 快取雲端資料 | — |

## 3. 資料與外部串接
### 3.1 一筆資料的欄位（試算表一列）
| 欄位 | 說明 |
|------|------|
| id | 手機端產生的唯一碼（防止重送時重複） |
| createdAt | 建立時間 |
| updatedAt | 最後修改時間 |
| category | 烘焙／烹飪／手作／金句／好文（預設：必選一個，見 §7） |
| keywords | 使用者打的文字，原樣保存 |
| link | 原始網址，可空白 |
| photoId | 照片在雲端硬碟的檔案 id，可空白 |
| photoUrl | 顯示用的照片網址 |

照片和連結至少要有一個，不然不能儲存。

### 3.2 外部串接
- **Google 雲端硬碟**：資料夾「靈感收藏」放照片；刪除時丟進垃圾桶
- **Google 試算表**：「靈感收藏資料庫」一張工作表
- **Apps Script 網頁應用程式**：以使用者本人身分執行、存取權設「任何人」，靠通行碼擋外人。網頁用 `text/plain` 的 POST 呼叫，避開瀏覽器跨網域預檢
- **GitHub Pages**：放網頁檔案

### 3.3 資料怎麼流動
1. 新增：貼上照片 → 縮圖壓縮 → 連同欄位存進送出佇列（排隊中）→ 送給雲端小程式 → 照片寫進雲端硬碟、資料寫進試算表 → 回傳成功 → 佇列移除 → 顯示「已存入 😊」
2. 搜尋：打開搜尋分頁 → 向雲端小程式拿全部資料（文字＋照片網址，先顯示上次的快取）→ 在手機上比對
3. 修改／刪除：點開一筆 → 修改分類或關鍵字／刪除 → 送給雲端小程式 → 更新清單

## 3.4 設計方向
**色系：灰藍｜調性：俐落、極簡乾淨**（使用者選定）

| 用途 | 色碼 | 用在哪 |
|------|------|--------|
| 主色 | `#4A6378` 灰藍 | 儲存按鈕、選中的分類、分頁標示 |
| 輔色 | `#8FA3B3` 霧灰藍 | 未選中分類的外框、圖示 |
| 強調色 | `#2F7A5B` 沉綠 | 「已存入 😊」 |
| 提醒色 | `#B7791F` 琥珀 | 「排隊中」數字 |
| 背景 | `#F4F6F8` 霧白 | 整頁底色 |
| 卡片 | `#FFFFFF` | 清單列、輸入區 |
| 文字 | `#1F2A33` 深墨 | 主要文字 |
| 次要文字 | `#66737F` | 時間、連結網域 |
| 分隔線 | `#DDE3E8` | 列與列之間 |

分類小色點（只用在清單左側一顆小圓點，幫助一眼分辨）：烘焙 `#A9744F`、烹飪 `#6F8A4E`、手作 `#5F74A8`、金句 `#9A6A88`、好文 `#4F8C8C`

**字體方向**：標題與內文都用手機內建的無襯線黑體（思源黑體／Noto Sans TC 方向），標題稍粗；不用裝飾字體。

**版面原則**
- 新增畫面由上到下：照片貼上區（大，點一下就能貼上或選圖）→ 連結欄 → 五個分類按鈕（一排，拇指點得到）→ 關鍵字欄 → 最下方整寬「儲存」按鈕
- 儲存按鈕固定在畫面下方，單手拇指就能按
- 搜尋畫面：上方搜尋框＋分類按鈕，下面一列一筆
- 底部只有兩個分頁：新增、搜尋（設定藏在搜尋頁右上角）

**設計理由（對使用上的幫助）**
- 截圖本身顏色很多，底色用霧白、灰藍，照片才是畫面主角，掃一眼就認得出是哪一則
- 儲存按鈕放在拇指位置、分類一排點選，存一則的時間就是「貼上、點分類、打兩個詞、按儲存」
- 「已存入」用綠色、「排隊中」用琥珀色，一眼就知道有沒有存好，不用擔心掉資料

## 3.5 技術選型
| 項目 | 選用 | 為什麼（白話） | 費用 |
|------|------|----------------|------|
| 語言／框架 | 單純 HTML＋CSS＋JavaScript（由我選定，使用者同意） | 只有兩三個畫面，不需要框架；練習時每一行都看得懂 | 0 |
| 資料存哪 | Google 試算表＋雲端硬碟（使用者同意） | 符合原本想法；用使用者月費方案的空間；試算表兼當看得到的備份 | 0，不綁卡 |
| 曾比較：Firebase | 未採用 | 較快較穩，但照片儲存須綁卡升級 Blaze 方案 | 用量內約 0，但要綁卡 |
| 主機部署 | GitHub Pages（使用者同意） | 使用者已會操作 | 0 |
| 後端 | Apps Script 網頁應用程式，手動貼上部署（由我選定） | 免費、掛在自己 Google 帳號下；一般帳號額度對每天幾十筆綽綽有餘 | 0 |
| 外部服務 | 無其他 | — | 0 |
| AI 模型 | 不使用（使用者同意） | 搜尋只需要文字比對；口說輸入錯字多，使用者決定用打字 | 0 |
| 知識怎麼存 | 不適用；搜尋在手機端比對 | 單字、部分比對、多詞交集都能瞬間完成 | 0 |
| 照片顯示 | 雲端硬碟檔案設「知道連結的人可檢視」（使用者同意） | 工具才能直接顯示小圖；代價是拿到網址的人可看到照片，但網址是亂碼 | 0 |
| 測試工具 | Vitest＋jsdom＋fake-indexeddb；指令 `npx vitest run` | 可測搜尋、佇列、畫面行為；剪貼簿與分享另做手機實測 | 0 |

**整體**：月費 0 元、不綁卡｜平常不用維護，改程式才需要重新推上 GitHub、改後端才需要重新部署 Apps Script｜換人接手容易，都是常見服務。

- [ ] **T05 雲端小程式（Apps Script）**
  - 目標：save／list／update／delete 四個動作與通行碼檢查
  - 測試先行（邏輯拆成純函式，用 Vitest 測；Google 服務用假的物件代替）：
    - 通行碼錯 → 回錯誤，不寫入任何東西
    - save 新 id → 新增一列＋建立照片檔

    - update → 只改分類、關鍵字、updatedAt
    - delete → 刪除該列，照片丟進垃圾桶
    - list → 回傳全部列的文字與照片網址
  - 手機實測清單：照著部署說明貼到 Apps Script、部署成網頁應用程式，用瀏覽器送一筆，試算表與雲端硬碟各出現一筆
  - 產出：backend/logic.js、backend/Code.gs、backend/部署說明.md、tests/backend.test.js
